## Что имеем?

### Подразделения
 - В структуре компании выделяются четыре подразделения:
 - Головной офис.
 - Клиники.
 - ИИ-сервисы для работы с медицинскими данными в виде отдельной компании.
 - Финтех-сервисы в виде отдельной компании с банковской лицензией.

### Технологии
 - Сейчас развёрнуты такие технологии, сервисы и приложения:
 - DWH на базе Microsoft SQL-сервера 2008 года.
 - Power BI.
 - Power Builder.
 - Шина на базе Apache Camel.
 - ИИ-сервисы на Python.
 - Финтех-сервисы на Golang и Java.

### В DWH лежат:
 - Данные по клиентам.
 - Медицинские карты и истории болезни, в том числе — данные исследований, выполненных в ходе лечения. 
 - Финансовая история. 
 - Счета. 
 - Данные о кредитах. 
 - Данные по персоналу больницы. 
 - Данные по инвентаризации. 
 - Финансовая отчётность и много другой информации.

### Какие проблемы?
 - В одной куче лежат медицинские и финансовые данные
 - Очень много данных, по которым не получается строить нормальные отчеты, либо их выгрузка занимает часы
 - Замедляется time-to-market

## Что нужно?

### Поработать над продуктами
 - Финтех-сервисы.
 - Внутренняя медицинская система-DWH с клиентским интерфейсом и дополнительной бизнес-логикой под финтех- и ИИ-сервисы.
 - Много кастомизаций BI-системы поверх DWH.
 - ИИ-сервисы для работы с медицинскими данными.
 - Слой интеграций через старую шину данных.

Сформировать архитектурное решение по трансформации. 
Уточнить границы доменов и связи между ними. 
Запланировать конкретные проекты в доменах по развитию «витрины данных».

### Предлагаемые домены
 - Медицина
 - Банк
 - ИИ
 - Корпоративные данные

### Предлагаемое решение по витрине данных
 * Необходимо организовать DataMesh систему, в каждой доменной области выделить специалистов, которые будут владеть данными.
 * Необходимо разделять данные разных доменов по разным хранилищам (временно можно интегрировать текущие хранилища)

### Приоритеты
 1. Внедрение витрины данных, для быстрого доступа к нужным данным и уменьшения time-to-market
 2. Выделение отдельных доменов и обучение персонала работы в своем домене
